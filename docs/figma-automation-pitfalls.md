# Figma 자동화에서 반복해서 밟은 함정

2026-08, ASO 스크린샷 9개 언어를 자동 생성하면서 실제로 밟은 것들만 적었다.
전부 **"도구는 성공을 응답했는데 화면은 그대로"** 라는 형태로 나타나서, 응답만 보고 넘어가면
같은 자리를 몇 번씩 돈다. 실제로 그렇게 돌았다.

## 0. 제1원칙 — 쓰고 나면 반드시 다시 읽어서 확인한다

`move_node`·`mirror_horizontal`·`set_multiple_text_contents` 는 **아무 일도 안 일어나도
성공을 돌려준다.** 아래 세 가지가 대표적이다.

| 쓴 것 | 아무 일도 안 일어나는 경우 |
|---|---|
| `move_node(x,y)` | 부모가 가로 오토레이아웃 → 레이아웃이 즉시 되돌린다 |
| `mirror_horizontal(position)` | 자식이 부모와 같은 폭 → `W - 0 - W = 0`, 항등식 |
| 무엇이든 | 화면에 안 보이는 **가려진 사본**을 건드렸다 |

그래서 **한 번에 여러 개를 적용하지 말고**, 적용 → 좌표 재조회(또는 렌더) → 확인을 반복한다.
21개를 한꺼번에 뒤집었다가 어느 게 먹고 어느 게 안 먹었는지 몰라 전부 되돌린 적이 있다.

## 1. 같은 자리에 사본이 여러 벌 쌓여 있다

디자인 파일에는 **같은 좌표에 겹쳐 둔 대안 사본**이 흔하다. 이름도 같다.
탭 행 하나를 뒤집으려다 **가려진 사본 3벌을 차례로 뒤집고** 나서야 진짜를 찾았다.

**찾는 법** — 이름이 아니라 **효과로** 찾는다. 후보를 하나 바꾸고 렌더가 변하는지 본다.
변하지 않으면 그건 가려진 사본이다.
`get_node_info` 는 `visible`·`opacity` 를 돌려주지 않아서 정적으로는 판별할 수 없다.

## 2. 오토레이아웃이면 좌표가 아니라 **순서**다

가로 오토레이아웃 컨테이너의 자식은 x 를 써도 레이아웃이 다시 계산한다.
RTL 로 뒤집으려면 **자식 순서를 뒤집어야** 한다(`mirror_horizontal` 의 `order` 모드).

넘치는 행(뷰포트보다 넓은 스크롤 행)은 순서만 뒤집으면 **첫 항목이 화면 밖으로 나간다.**
정렬(`set_axis_align` 의 `primaryAxisAlignItems: MAX`)까지 같이 바꾸고, 필요하면 컨테이너
폭을 클리핑 영역에 맞춰 줄인다. 세 가지를 다 해야 비로소 맞는다.

## 3. 인스턴스 내부는 순서도 좌표도 못 바꾼다

```
order    → "Cannot move node. New parent is an instance or is inside of an instance"
position → "This property cannot be overridden in an instance"
```

마스터를 고치면 **모든 언어가 같이 바뀌므로** 그 행만 `detach_instance` 로 분리한다.
ASO 자산은 일회성 산출물이라 컴포넌트 연결이 끊겨도 잃는 게 없다.

## 4. 중첩된 컨테이너를 둘 다 뒤집으면 안쪽이 두 번 뒤집힌다

가로 컨테이너를 기하로 자동 검출하면 **부모와 자식이 같이 잡힌다.** 둘 다 뒤집으면 안쪽은
원위치로 돌아와서, 어떤 행은 바뀌고 어떤 행은 그대로인 **뒤죽박죽**이 된다.

→ 검출할 때 **조상이 이미 대상이면 자식은 건너뛴다.** 최상위만 뒤집는다.

## 5. 텍스트 정렬은 개별 노드가 아니라 컨테이너로

`set_text_align(RIGHT)` 을 텍스트 노드에 직접 걸면, 박스가 넓은 경우 **옆 열을 침범한다.**
`set_axis_align(counterAxisAlignItems: MAX)` 로 **컨테이너를 정렬**하는 게 맞다.

그리고 `set_text_align` 은 **폰트가 로드돼 있어야** 한다. 같은 세션에서 그 노드에
텍스트를 한 번 쓰면(`set_multiple_text_contents`) 이후 호출이 통과한다.

## 6. `characters` 대입은 구간별 스타일을 뭉갠다

Figma 는 `node.characters = "..."` 시 **첫 글자 스타일을 문자열 전체에 바른다.**
"큰 제목 + 작은 해시태그" 처럼 한 노드에 크기가 섞여 있으면 조용히 균일해진다.
`get_text_segments` 로 읽고 `set_text_segments` 로 쓴다.

## 7. `clone_node` 두 가지

- **`parentId` 를 주면 x/y 가 부모 기준 상대좌표**로 해석된다. 절대좌표를 넣으면 컨테이너
  바깥으로 날아간다(섹션 밖에 프레임이 떨어져 한참 헤맸다).
- **`name` 은 레이어 이름만 바꾼다.** TEXT 노드의 내용은 그대로다. 라벨을 복제하면
  레이어는 `IT`, 화면에 찍히는 글자는 여전히 `DE` 다.

## 8. 번역 맵을 중간 언어를 거쳐 합성하지 말 것

`zh→en` 과 `zh→it` 를 합쳐 `en→it` 를 만들면, **영문 쪽에 중복 키가 있을 때 뒤 값이 이긴다.**
요일 `M T W T F S S` 는 `T`·`S` 가 중복이라 화·목이 뭉개져 `L G M G V D D` 가 나왔다.

→ 요일·숫자처럼 **위치가 의미인 것은 문자열 매핑이 아니라 x 좌표 순서로** 넣는다.

## 9. export 가 1×1 로 나오면 노드가 클리핑된 것이다

프레임이 다른 프레임 **안으로 들어가 버리면**(드래그 실수, 또는 스크립트의 잘못된 reparent)
바깥 프레임이 잘라내서 렌더가 비고, export 는 1×1 투명 PNG 를 돌려준다.
노드 자체는 멀쩡히 존재하고 자식 좌표도 정상이라 정적 조회로는 안 드러난다.
→ **부모를 확인**하고, 섹션으로 다시 꺼낸다(`clone_node` 에 `parentId` 를 주고 원본 삭제).

마스크 노드도 단독 export 하면 1×1 이 나온다. 마스크의 이미지는 꺼낼 수 없으므로
성한 형제에서 `copy_image_fill` 로 hash 를 옮긴다.

## 10. 릴레이 운용

- **채널 ID 는 플러그인을 다시 실행할 때마다 바뀐다.** 타임아웃이 나면 먼저
  `list_figma_channels` 로 `hasFigma: true` 인 채널을 찾는다.
- 큰 base64 는 argv 상한(~1MB)에 걸린다 → `figma-test-client.mjs` 의 `@file` 형식.
- 명령이 100건을 넘으면 셸 타임아웃에 걸린다 → `figma-batch-client.mjs` 는 명령마다
  결과를 흘려 쓰고, 다시 실행하면 **명령 해시로 앞부분을 건너뛴다**(`--fresh` 로 무시).

## 11. 워프(기울어진 목업) 실측 결론

- 출력 해상도가 필터보다 지배적이다. `MAX_SIDE`(4096) 까지 키워 뽑고 축소는 Figma 에 맡긴다.
  x3 기본값이면 정답지 대비 MAE 0.5/255 로 육안 구분이 안 된다.
- 기기 목업의 `Screen` 그룹은 **RECTANGLE(둥근 모서리 알파 마스크) + VECTOR(내용 슬롯)** 두 겹이다.
  마스크 쪽을 단색으로 덮으면 모서리가 각진다.
- 유리 너머 화면은 톤이 눌린다. 실측하면 채널 공통 선형 변환(`out = 0.851·in + 21`) 하나로 맞는다.
  기준점 세 개(배경·강조색·흰색)를 각각 원본과 대조해 구하면 된다.
